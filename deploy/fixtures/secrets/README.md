# Development secrets

Development fixtures, **committed on purpose**. They are **not secrets**: anyone who reads the repository knows them. A deployment mounts credentials from its own secret manager and never bakes them into an image, a repository file or an environment variable.

| File | Contents |
| --- | --- |
| `access-context.token` | The deployment's credential for Access's access context contract. |
| `cursor.key` | Key that signs page cursors. At least 32 bytes; not a gateway key. |
| `identity.public.pem` | The local gateway's **public** key. The private half is not in the repository: the local gateway holds it, generated by `bun run scripts/dev-keys.ts`. |
| `identity.key` | The gateway's **legacy** derived key (`HS256`). It can sign, so it belongs inside the gateway's trust boundary. The legacy format is refused by default and is removed in platform version `2.0.0`. |

The metrics endpoint token is deliberately **absent**: without its file the endpoint does not exist and answers `404`. To enable it, write a token file and point `DATA_METRICS_TOKEN_FILE` at it.

The [development stacks](../../compose/platform.compose.yaml) and CI mount this directory read-only at `/run/secrets`. The bindings naming the gateway's public key are in [`../bindings.json`](../bindings.json).
