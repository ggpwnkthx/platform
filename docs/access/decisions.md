# Decisions

The design decisions behind the Access contract, each with the evidence that backs it. It is written for maintainers; the [specification](spec.md) is normative, and [platform decisions](../platform/decisions.md) defines this table and when a decision changes the contract.

| # | Question | Decision | Stated in | Status | Evidence |
| --- | --- | --- | --- | --- | --- |
| 1 | Where does multi-tenancy live? | In Access, never in the gateway. A gateway keeps one provider and one Access deployment, so one gateway deployment serves one tenant. | §1.4 | resolved | `src/domains/identity/tenant.ts`, `test/contract/shared-client.test.ts` |
| 2 | Is Access an OpenID Connect provider or client? | Both: a client of each tenant's provider and a provider for the gateway. The gateway does not need to know. | — | resolved | `src/domains/provider/service.ts`, `src/domains/provider/discovery.ts` |
| 3 | What keys an identity mapping? | `(tenant, provider, subject)`. Never the e-mail: it is mutable and not an identity. The provider is in the key because two providers of a tenant hand out the same `sub`. | §6.2 | resolved | `src/domains/identity/mapping.ts`, `test/contract/login.test.ts` |
| 4 | Is a principal created at first login? | Only when the tenant has `auto_provision = true`, and then with no grant: login succeeds, access does not. | §6.4 | resolved | `src/domains/identity/mapping.ts`, `test/contract/login.test.ts` |
| 5 | What decides access? | The grants table alone. Request roles are a token snapshot; reading them would honor a revoked grant until the next login. | §8.4 | resolved | `src/domains/authorization/decision.ts`, `test/contract/decisions.test.ts` |
| 6 | Does Access cache decisions? | No. The table is the truth, the query is one statement over indexed tables, and revocation latency is the gateway's cache TTL. | §8.6 | resolved | `src/domains/authorization/decision.ts`, `test/integration/decision-rule.test.ts` |
| 7 | How many administrative endpoints? | Twelve (seven that change, five that list) plus one that reads the audit. Nothing else changes tenants, principals or grants, so the audit is complete. | §10 | resolved | `src/domains/administration/service.ts`, `test/contract/administration.test.ts` |
| 8 | Why store the authorization code instead of making it self-contained? | A self-contained code can be redeemed twice within its lifetime. Storing it makes it single use, which the gateway relies on. | §5.5 | resolved | `src/domains/provider/code.ts`, `test/contract/login.test.ts` |
| 9 | Who holds a refresh token? | Only a client that keeps a session of the caller. The gateway holds none: it keeps a session of its own and does not read the data with the token of the caller. The console asks for one with the scope `offline_access`, and renews the token of the caller on the server, so the caller signs in once and not every five minutes. | §7.6 | resolved | `src/domains/provider/refresh.ts`, `src/domains/provider/tokens.ts` |
| 10 | Why is the denial reason free text? | The gateway hides it and only counts it. The reason vocabulary lets the gateway's count separate a missing role from every other denial. | §8.7 | resolved | `src/domains/authorization/decision.ts`, `test/contract/refusals.test.ts` |
| 12 | Where does the registration of a provider live? | In a table of its own, `tenant_providers`, and not in the row of the tenant. A tenant signs its people in at one or more providers, and the row of the tenant keeps the registration of the **default** one only, because that is what the administration writes. The slug of a provider never changes: a principal carries it. | §3.11 | resolved | `src/platform/postgres/providers.ts`, `src/domains/identity/provider-driver.ts`, `test/integration/providers.test.ts` |
| 11 | Which address does the audit hold? | The address of the socket, unless the deployment is behind an ingress that is the only way in (`ACCESS_INGRESS_ONLY`): the ingress reports the address of the caller in `x-real-ip`, and the audit names the operator that made the change. The limiter of the administration keeps the address of the socket: a header is a value the caller controls. | §10.1 | resolved | `src/domains/forwarding/address.test.ts`, `test/contract/caller-address.test.ts` |
