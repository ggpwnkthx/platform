# Security

The access service's security model, an item-by-item review, and the open findings. The rules themselves are in [spec.md](spec.md) §2.1 (invariants) and §3.10 (tenant isolation).

## Model

| Surface | Protection |
| --- | --- |
| Browser login | Login state is encrypted, authenticated and single use. The code is opaque, stored hashed, single use, and bound to the client, redirect URI and PKCE challenge. The provider's token is validated before any row is read. |
| Decisions | The gateway authenticates with a bearer token or its tenant's credentials, compared in constant time. Tenant rules are enforced by the database (row level security). Tenant credentials are always scoped to their tenant. The deployment bearer token is optional and deprecated; without it, only tenant credentials are accepted. |
| Administration | One platform-wide bearer token or per-tenant credentials, compared in constant time, with a per-address rate limit spent only by failed calls. Every call is audited in a table. Secrets are write-only. |
| Secrets at rest | A tenant's two client secrets are encrypted with AES-256-GCM under a key derived with HKDF-SHA256 from the deployment secret. |
| Image | Non-`root` user, no shell, no build tools, base image pinned by digest, build fails on findings above "high", SBOM published. |

## Review

| # | Item | Result | Where |
| --- | --- | --- | --- |
| 1 | **Identifier enumeration.** Admin endpoints return the ids they create, behind the admin token. Decisions answer `the principal does not exist` or `the principal does not have the role of the workspace`, which reveals whether a subject exists. The only caller is the trusted gateway, which hides the reason. | Accepted | `src/domains/authorization/decision.ts` |
| 2 | **Response timing.** Admin, decision and metrics tokens are compared in constant time; both values are hashed first, so timing does not depend on secret length. Login state is authenticated: tampered state does not decrypt. | Fixed | `src/observability/secrets.ts`, `src/domains/identity/state.ts` |
| 3 | **SQL injection.** Every statement is parameterised. Table and column identifiers are code constants; caller input never reaches a statement as text. | No finding | `src/platform/postgres/` |
| 4 | **SSRF via `idp_issuer`.** The service calls the issuer a tenant registers. Before the call, the host is resolved and every resolved address must be public. Production refuses private addresses; development accepts them (test fixtures use loopback). | Fixed | `src/platform/bun/address.ts` |
| 5 | **Provider redirects.** Calls to tenant providers do not follow redirects, so a provider cannot divert the deployment's credentials. | Fixed | `src/platform/bun/http.ts` |
| 6 | **XSS on refusal pages.** Login refusal pages escape everything they display. | Fixed | `src/app/pages.ts` |
| 7 | **Secrets in logs.** The logger redacts tokens, secrets, cookies, passwords and `Authorization` headers in fields and message text. Statement values are never logged, only the statement. | Fixed | `src/observability/logging.ts`, `src/platform/postgres/trace.ts` |
| 8 | **Secrets at rest.** Both client secrets are encrypted with AES-256-GCM under `ACCESS_SECRET_ENCRYPTION_KEY` before writing. Without a key, the service refuses to write a tenant; it never stores a secret in clear. | Fixed | `src/platform/postgres/secrets.ts` |
| 9 | **Login state.** Encrypted, authenticated, single use (deleted whatever the callback outcome), ten-minute lifetime. | Fixed | `src/domains/identity/state.ts` |
| 10 | **Authorization code.** Opaque, stored as a hash, 60-second lifetime, single use, bound to the client, redirect URI and PKCE challenge. | Fixed | `src/domains/provider/code.ts`, `src/domains/provider/exchange.ts` |
| 11 | **Failure is denial.** A database or store outage, a slow provider and a decision timeout all end in denial: the gateway fails closed on anything but a successful answer. | Fixed | `src/app/decisions.ts` |
| 12 | **Reasons never reach callers.** Reasons are for operators and go to the decision log. The decision response carries the reason because the gateway contract requires it; the gateway hides it. | Accepted | `src/app/decisions.ts` |
| 13 | **Image.** Runs as non-`root`, has no shell and no build tools. Base image pinned by digest. | Fixed | `Dockerfile` |
| 14 | **Database password.** Not in the image; it comes from the environment, and rotation means deploying a new secret. | No finding | `src/runtime/env.ts` |
| 15 | **Admin rate limit.** Bursts of failed authentication get `429`, and an address that exhausted its budget is refused whatever it presents. Failure counts live in the deployment's shared store, so the window is deployment-wide, not per replica. | Fixed | `src/domains/administration/limiter.ts`, `src/platform/redis/store.ts` |
| 16 | **Process limits.** Admin bodies are at most 64 KiB; provider calls have a deadline (`ACCESS_IDP_TIMEOUT_MS`), and so do decisions (`ACCESS_DECISION_TIMEOUT_MS`). | Fixed | `src/app/administration.ts`, `src/domains/identity/provider-client.ts` |
| 17 | **Browser redirects.** The gateway's redirect URI is caller-controlled, so it is checked against the gateway's registered URIs before the tenant is resolved. An unregistered URL gets `400 invalid_request` on an access service page; the browser is not sent there and the URL never receives a code. | Fixed | `src/domains/identity/tenant.ts`, `src/app/login.ts` |
| 18 | **Cookies.** The login state cookie is `HttpOnly`, `SameSite=Lax`, `Secure` in production, with its path set to the login callback. | Fixed | `src/app/login.ts` |
| 19 | **Decision credentials.** Two schemes (§8.8): the deployment bearer token, used by the reference gateway and **not scoped**, and tenant credentials, scoped to their tenant. A gateway using tenant credentials that asks about another tenant's principal gets the "principal does not exist" answer. | Fixed | `src/app/decisions.ts` |
| 20 | **Tenant isolation.** The application isolates tenants, and the database backs it up: all eight tables have PostgreSQL row level security with the statement's tenant as policy. A statement that omits the tenant is refused by PostgreSQL. The scope is transaction-local, so a pooled connection never carries another request's scope. Production refuses to start with a role that bypasses policies. | Fixed | `src/platform/postgres/scope.ts`, `src/platform/postgres/migrations/0003_tenant_isolation.sql` |
| 21 | **Secret rotation.** Client-presented secrets rotate with no window where client and service disagree: a tenant's replaced gateway secret stays valid for 24 hours, and environment tokens are read from two variables during rotation. Both are compared in constant time. | Fixed | `src/app/decisions.ts`, `src/app/oauth.ts`, `src/domains/administration/service.ts`, `docs/access/spec.md` §4.3.1 |
| 22 | **Admin audit.** The audit is a table, not a log line, which would vanish with the container and cannot be queried. Rows identify the operator by the calling credential's fingerprint, never the secret. The same statement writes the change and its row, so both commit or neither does. | Fixed | `src/platform/postgres/audited.ts`, `src/platform/postgres/audit.ts`, `src/app/administration.ts` |
| 23 | **Statement deadline.** The decision deadline is enforced server-side: the pool connection's `statement_timeout` stops a slow statement and returns the connection to the pool at once. A process-only deadline would let a statement hold a connection for the whole pool timeout. | Fixed | `src/platform/postgres/postgres.ts`, `src/platform/postgres/decisions.ts` |
| 24 | **Per-tenant permissions.** A permission key is a name *within* a tenant: the unique index is on `(tenant, key)`, so each tenant has its own row for a key and a grant never names another tenant's row. Platform catalogue permissions are shared by all tenants. | Fixed | `src/domains/administration/service.ts`, `src/platform/postgres/permissions.ts` |
| 25 | **Admin credentials.** A deployment may define per-tenant credentials, each acting only for its tenant and optionally naming its operator. A call naming another tenant is `403 forbidden`; lists are limited to the tenant, and query filters cannot widen them. The audit names the operator, not a shared secret's fingerprint. | Fixed | `src/domains/administration/credentials.ts`, `src/domains/administration/service.ts`, `src/runtime/composition.ts` |
| 26 | **Platform-owned tenant flags.** `shared_client` moves platform logins and `is_default` routes shared-client logins. A tenant credential may not change them: sending a value different from the stored one is `403 forbidden`. | Fixed | `src/domains/administration/service.ts` |
| 27 | **Decision scope ignores tenant row flags.** Gateway credentials are scoped to their tenant, shared client or not: scope comes from the credential, never from a row flag. The deprecated deployment bearer token is the only unscoped scheme. | Fixed | `src/app/decisions.ts` |
| 28 | **Checked address is the called address.** The address guard resolves the provider host and pins the resolved address; the call goes to that address with the host name in the `Host` header and certificate check. DNS that returns a public address to the check and a private one to the connection gains nothing. | Fixed | `src/platform/bun/address.ts`, `src/platform/bun/http.ts` |
| 29 | **Only failed calls spend the limiter budget.** An authenticated call is answered regardless of earlier failures from its address, so an attacker cannot lock out the token holder. The budget still stops a caller hammering the endpoint. | Fixed | `src/domains/administration/service.ts`, `src/domains/administration/limiter.ts` |
| 30 | **Response headers.** Every response carries `x-content-type-options`, `x-frame-options` and `referrer-policy`; refusal pages carry a `content-security-policy`; token responses carry `cache-control: no-store`. | Fixed | `src/app/app.ts`, `src/app/oauth.ts` |

## Open findings

| # | Finding | Severity | Plan |
| --- | --- | --- | --- |
| 1 | A decision's reason tells the gateway whether a subject exists. | Low | The gateway is the only caller and hides the reason. A reason that reveals nothing would change the §8.7 vocabulary, which is a spec change first. |
| 2 | The decision bearer token is not scoped: a gateway presenting it may ask about any principal on the platform, and every gateway in the deployment shares the secret. | Medium | The reference gateway only speaks the bearer token, so the scheme cannot be removed without a gateway change. Deployments move their gateways to scoped tenant credentials (§8.8), which removes the shared secret's power. The token is **optional**: without `ACCESS_DECISION_TOKEN`, only tenant credentials are accepted and the bearer scheme is refused (§4.4). Rotation is rolling (the replaced token stays valid until removed, §4.3.1), so gateways need not change simultaneously. The token is **deprecated**: the first decision that presents it logs a one-time notice naming the replacement scheme. Tenant credentials are always tenant-scoped, shared client or not (item 27), so the shared token is the only scheme that reaches every tenant. |
| 3 | A tenant may register a provider over plain `http`, so the tenant's provider secret and the id token travel in clear. | Low | Refusing `http` issuers would change the contract for deployments whose provider uses plain http. The called address is the checked one (item 28), and provider responses are read up to 1 MiB. A deployment that wants the rule registers tenants with `https` issuers and watches the logs. |

Every finding is "low" except the second, whose plan is a deployment migration rather than a service change.
